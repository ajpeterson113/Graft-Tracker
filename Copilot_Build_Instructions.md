# Build Instructions for Microsoft Copilot — BIOT Chicago West Graft Tracker

**Who you are building for:** AJ Peterson, Account Manager, Smith+Nephew Bio Tissue (BIOT Chicago West).
**Read first:** `Copilot_Overview.md` — it holds every business rule, column, status, pricing and account rule. Nothing in that file changes here; this file says how to build it inside Microsoft 365.
**Goal:** Rebuild the three apps and the automation described in the overview using Microsoft 365 tools only, so they update themselves from AJ's Outlook calendar, his Outlook inbox, and his taps — no GitHub, no manual re-uploading of the Excel file.

---

## 0. Platform decisions (read before building)

| Need | Use | Why |
|---|---|---|
| Data that several apps share and that must update in real time | **SharePoint lists** (one site, "Chi West Graft Tracker"), or **Dataverse** tables if the tenant allows Dataverse for Teams | Lists are live; an app, a flow and an Excel export all read the same rows. The Excel workbook becomes an *output*, not the database. |
| The phone apps | **Power Apps canvas apps** (phone layout), published to the Power Apps mobile app and pinned in Teams | Works on both iPhones; buttons write straight to the lists. |
| "Ask the tracker a question" / file an upload by chatting | **Copilot Studio agent** ("Chi West Tracker") with the lists as knowledge and agent flows as tools, published to Teams and M365 Copilot | Lets AJ type "file the uploads" or "M.D. grafted today 16mm" and have it done. |
| Email- and calendar-driven updates | **Power Automate cloud flows / Copilot Studio agent flows** with Office 365 Outlook triggers (*When a new email arrives (V3)*, *When an event is added, updated or deleted (V3)*) | Event-driven, so updates land within a minute of the email/calendar change. |
| Reading case sheets, stickers, POs and shipping reports from photos/PDFs | **AI Builder** document processing / text recognition, or a **prompt action** in an agent flow (GPT reads the image and returns JSON) | Replaces Claude reading the photo. AI Builder needs credits/licensing — confirm with IT. |
| The master Excel file AJ opens on the laptop | **Excel on SharePoint**, regenerated by a flow (Office Scripts) from the lists, or an Excel table linked to the list | Download link = the SharePoint file URL. |

**Do you still need GitHub?** No. SharePoint replaces it as the laptop-readable home for the Excel files and the read-only pages (SharePoint pages or Power BI/Power Apps views).

**Do you still need scheduled tasks?** Mostly no — email and calendar triggers replace the morning filing run. Three schedules remain useful: a Sunday-evening coverage email to Caroline and Pete; a Friday-night flow that clears coverage; a nightly flow that regenerates the Excel exports and the period snapshot.

**Prerequisites to confirm with IT:** Power Apps/Power Automate licenses (often included in M365 E3/E5), permission to create SharePoint lists and flows, AI Builder credits, Copilot Studio access, and whether personal mailboxes may be used as flow triggers.

## 1. Data model — SharePoint lists (or Dataverse tables)

Create these lists on one SharePoint site. Column names mirror the overview so the Excel export matches the existing tracker.

### `Applications` (= the month tabs + Pieces)
Application Date · Initials · Alexian ID · Account (lookup → Accounts) · Surgeon · Product (GRAFIX / STRAVIX / OASIS) · Size · Lot · Unit SN · Lot/SN (all pieces) · Pieces · REF · Expiry · Price · PO Number · PO Received (date) · PO Match (Certain / Unconfirmed) · PO Status (Outstanding / Received) · Submitted (blank / Submitted / In SFDC) · SFDC Invoice · Period (P10, P11 …) · Month Tab · Application # · Case Sheet (attachment or link) · Notes · Row State (calculated: Waiting on PO / Ready to submit / Submitted / In SFDC).

### `PurchaseOrders`
PO Number · Account · Date Received · Patient ID / Initials · Product · Size · Qty · Price · Source email link · Matched Application (lookup) · Match status.

### `Patients` (= Chi West Patients app)
Account · Patient ID · Initials · Full name (hidden column, shown on tap) · Status (Pending / Potential New Start / Grafting / On hold / OR / Done / Denied) · Provider · Coverage · PA required · Product · Size · Frequency · Application Count · Last Graft · Case Date (Stravix) · Next Appointment · Cover (AJ / Caroline / Pete) · Verify flag · No-follow-up flag · Notes (multi-line, dated).

### `Events` — lunches, in-services, OR cases, meetings (title, kind, place, date, time, end, note).
### `Stock` — Account · Product · Size · On hand · Target min / max · Use per week · Reorder flag.
### `Prices` — Account · Product · Size · Contract price (one row per combination).
### `Accounts` — Name · Type (WCC / Office / OR) · Rules (bill & replace, weekly default, 8-app cap, PO by patient ID, no case sheets).
### `Periods` — Period · Start · End · Shipping days · Target · Commission rate.
### `Targets` — the 181 prospects from `Chi_West_Surgeon_Targets.xlsx` (Tier, Hospital, Name, Specialty, Practice, Office, Phone, NPI, claims columns, Existing customer).
### `Outreach` — Target (lookup) · Who (AJ / Caroline / Pete) · Date · Type (visit, call, lunch booked, email) · Objection · Note.
### `Uploads` — File · Type (Case sheet / PO / Sticker / Shipping report / Email) · Source (app, email, calendar) · Status (New / Filed) · Linked record.
### `Todos` — Task · Owner · Due · Done · Source.

Import the existing month tabs from `Graft_Tracker_BIOT_Chicago_West.xlsx` and the `All Patients` tab of `Chi_West_Patient_List.xlsx` as the starting data.

## 2. Automations (Power Automate / agent flows)

Build each with Copilot ("describe what you want") and then check the connections. All use AJ's Office 365 Outlook connection.

| # | Trigger | What the flow does |
|---|---|---|
| F1 | **New email arrives** with an attachment (PDF/image) or subject containing "PO", "purchase order", "case sheet", "implant record", "shipping report" | Save the attachment to `Uploads` (Status New). Run AI Builder / prompt action to extract: PO number, account, patient ID or initials, product, size, qty, lot/SN, date. If it's a PO → create a `PurchaseOrders` row and try to match an `Applications` row (Alexian by patient ID; others by account + initials + product/size; multi-unit POs match every unit). If matched → fill PO Number/Received, set Row State Ready to submit, write the PO into the case-sheet banner field. If it's a case sheet/sticker set → create the `Applications` row (Outstanding) and bump the patient's Application Count. If it's the shipping report (rows where Sales rep = "A JOSEPH PETERSON") → create rows for each sale order. Any line AJ typed above a forwarded email = instruction; forwarded text = information. Post a Teams message to AJ summarizing what was filed and anything it couldn't match. |
| F2 | **Calendar event added/updated/deleted** | Parse the title pattern `Dr. X, initials, A#, product size` (AJ's convention). Create or update the `Patients` row's Next Appointment; if the event is moved, set the Verify flag unless AJ's note says it's confirmed; if an event is deleted and the patient is Grafting, flag No follow-up. Events titled Lunch / OR / In-service / Meeting go to `Events`. Pending/On-hold patients not on the calendar are left alone. |
| F3 | **Row created/modified in `Applications`** | Fill Price from `Prices` when blank; set Period from `Periods`; recompute Row State and color; if account is Ascension St. Alexius or the product is an OASIS box on a PO, set Submitted = "Submitted (pending SFDC)" automatically. |
| F4 | **Email from SFDC / an SFDC export is saved to the "SFDC" folder** | Match invoices to `Applications` by PO number, then lot/SN, then account+date+product; set Submitted = In SFDC and store the invoice number. Accept a different Stravix serial at St. Alexius (bill & replace). |
| F5 | **Button in the canvas app** (Submitted / In SFDC / Grafted / Held) | Writes the status change; Grafted also creates the `Applications` row and attaches the photos. |
| F6 | **Scheduled — nightly 11 PM** | Regenerate `Graft_Tracker_BIOT_Chicago_West.xlsx` and `Chi_West_Patient_List.xlsx` on SharePoint from the lists (Office Script): month tabs, Pieces, Projections (rules in overview §4), Stock tabs, period snapshot; refresh the Good Samaritan "To Order" block. |
| F7 | **Scheduled — Sunday 6 PM** | Build and send the "Chi West Coverage" email to Caroline and Pete: their covered visits by day ("time Account – Dr. X, initials, product size") plus nearby drop-in targets. |
| F8 | **Scheduled — Friday 9 PM** | Clear the Cover field on all patients (coverage resets weekly). |
| F9 | **Stock change** | When On hand < Target min (Alexian WCC 5–10 each, 10–15 of 16mm; St. Alexius OR 7 each) → stock alert in the app and a Teams message. |

## 3. App 1 — Chi West Graft Tracker (canvas app, phone)

Screens, matching the current app:
1. **Home** — period pace line (shipping day X of Y from `Periods`, % of month, % to target), sales in SFDC + Submitted vs target, forecast upside/downside, four To-do tiles: Ready to submit (count + $), Waiting on a PO (count + $), Not in SFDC yet ($ + rows), Stock alerts.
2. **Cases** — current month rows; swipe/tap **Submitted** and **In SFDC**; filter by account, state; open the case sheet image.
3. **Uploads** — camera/file buttons "New case sheet" and "Upload PO" → `Uploads` (Status New). Show only unfiled items; filed items disappear.
4. **Projection** — Projections table by account (Sold / Upside / Downside), potential new starts, WCC stock offset.
5. **Stock** — per-account shelf counts and reorder flags.
6. **Full year** — monthly SFDC vs target table; periods and payouts; current period live, prior months fixed.

Style: Smith+Nephew colors — orange `#E9963E` accents/titles/outlined buttons, slate blue `#3F7097` action buttons, dark grey text. Bottom tab bar fixed. No explanatory text in the UI.

## 4. App 2 — Chi West Patients (canvas app, phone)

- **Schedule** (default "By time"; toggle By clinic) built from `Patients.Next Appointment` and `Events`; "+ Event" per day; Verify and No-follow-up badges; "To do" per clinic (pending IVRs, follow-ups, what to order).
- **Patients** list grouped by account, then status; cards show initials only, full name on tap; category dropdown incl. "No follow-up" and "OR".
- **Detail**: all fields, dated notes, files, **Grafted** button (photos → `Uploads`, Application Count +1, creates the `Applications` row as Waiting on PO the same day), **Held** button (sets next visit).
- **+ New patient** and **+ Notes** tiles (associate note photos → `Uploads`, status New until attached).
- No sales data in this app.
- Rules: new Alexian patients default Weekly; OR cases carry no application number; a Stravix OR patient followed in the office is one record under the office account.

## 5. App 3 — Chi West Targets (canvas app)

- **Today**: lunches booked, nudges (Sat/Sun/Mon: send the week email).
- **Plan**: route rows "My route · Caroline · Pete" built from each person's covered visits with nearby drop-ins (don't repeat stops already on AJ's or Caroline's route); "Copy for <name>" turns a day into text.
- **Log**: touches with Who picker; "Lunch booked" (date, time, where, who); objections per target.
- **Activity**: Me / Caroline / Pete views; metrics incl. lunches set up; one touch belongs to one person.
- Targets list with tier, hospital, specialty group (incl. "Office / scheduling contact"); the app may create new categories.

## 6. Copilot Studio agent — "Chi West Tracker"

- Knowledge: the SharePoint site (all lists) and `Copilot_Overview.md`.
- Tools (agent flows): File uploads (runs F1 logic on demand), Mark submitted / in SFDC, Add patient, Record graft ("X grafted today, 16mm"), Reschedule account ("move St. Joe's patients same time next week" → +7 days, Verify flag), Build coverage email, Build case sheet PDF from sticker photos (template = `Case Sheet.pdf`; stickers large in the table, date once, Each/Total in Unit Price), Fill transport log (template = `GRAFIX STRAVIX Transport Log 2.pdf`; reason "Needed same day", 7 AM transported / 8 AM received).
- Instructions: apply every rule in `Copilot_Overview.md` §2–§4; initials only, never full names in outputs; flag billing mistakes (a graft invoiced on another patient's PO).
- Publish to Teams and to Microsoft 365 Copilot so AJ can use it from Outlook and the Copilot app on his phone.

## 7. Laptop views

SharePoint pages (or a Power BI report) that mirror the GitHub README: Home (pace, To-do, this week, forecast, full year, download links), Cases, Projection, Stock, Patients by account, Targets. Download links point at the two Excel files on SharePoint.
